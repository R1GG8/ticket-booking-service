# Ticket Booking Service (Сервис бронирования билетов)

Production-ready backend-сервис для поиска и бронирования билетов на междугородний транспорт (поезда/автобусы) с динамическим ценообразованием, защитой от овербукинга и управлением транзакциями.

---

## Технологический стек
* **Язык:** Java 21
* **Фреймворк:** Spring Boot 3 (Spring Web, Spring Data JPA, Spring Validation, Spring Scheduling)
* **База данных:** PostgreSQL 16
* **Миграции БД:** Flyway
* **Контейнеризация:** Docker & Docker Compose
* **Тестирование:** JUnit 5, Mockito
* **Документация API:** OpenAPI 3.0 / Swagger UI
* **Сборщик:** Maven

---

## Ключевые инженерные решения

### 1. Защита от состояния гонки (Race Condition / Double Booking)
Для предотвращения одновременной покупки одного и того же места двумя пользователями применен механизм **пессимистической блокировки** на уровне базы данных (`PESSIMISTIC_WRITE`).  
В PostgreSQL запрос транслируется в `SELECT ... FOR UPDATE`, который блокирует строку места до завершения текущей транзакции.

### 2. Расчетный модуль динамического ценообразования (`PricingService`)
Стоимость билета вычисляется алгоритмически в реальном времени с использованием типа `BigDecimal`:
* Учет базового тарифа рейса.
* Коэффициенты класса обслуживания (Economy - x1.0, Coupe - x1.6, Business - x2.5).
* **Surge Pricing:** динамическая наценка +20% при падении числа свободных мест ниже 50% (высокий спрос).

### 3. Механизм удержания мест (Seat Hold c TTL) и фоновый воркер
* При оформлении брони место резервируется на **15 минут** (статус `PENDING`).
* Фоновый планировщик задач (`@Scheduled`) каждую минуту сканирует базу, выявляет неоплаченные протухшие брони (`EXPIRED`) и автоматически возвращает места в продажу (`FREE`).

### 4. Архитектура и надежность
* **Layered Architecture:** строгое разделение на Controller -> Service -> Repository.
* **DTO-паттерн:** полная изоляция доменных JPA-сущностей от внешнего API.
* **Централизованная обработка ошибок (`@RestControllerAdvice`):** возврат стандартизированных JSON-ответов с корректными HTTP-кодами (400 Bad Request, 404 Not Found, 409 Conflict).

## REST API Эндпоинты

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/v1/trips` | Поиск рейсов по городам и дате поездки |
| `GET` | `/api/v1/trips/{tripId}/seats` | Схема мест рейса с динамически рассчитанными ценами |
| `POST` | `/api/v1/bookings` | Бронирование места с пессимистической блокировкой |
| `GET` | `/api/v1/bookings/{bookingId}` | Получение информации об электронном билете |
| `POST` | `/api/v1/bookings/{bookingId}/confirm` | Подтверждение оплаты (перевод места в `SOLD`) |
| `POST` | `/api/v1/bookings/{bookingId}/cancel` | Отмена бронирования и возврат места в продажу |
| `GET` | `/api/v1/bookings/my?email=...` | Получение списка всех билетов пассажира по email |

## Запуск проекта за 1 минуту

Проект полностью контейнеризирован. Для локального запуска не требуется установленная Java или PostgreSQL - только Docker.

1. **Клонировать репозиторий:**
   ```bash
   git clone https://github.com/ВАШ_ЛОГИН/ticket-booking-service.git
   cd ticket-booking-service
Запустить через Docker Compose:
```
docker compose up -d --build
```
Открыть интерактивную документацию Swagger UI:
http://localhost:8080/swagger-ui.html

## Тестирование
Проект покрыт пирамидой тестов:
Unit-тесты: алгоритм расчета цен (PricingServiceTest).
Модульные тесты с Mockito: изоляция репозиториев и логика бронирования (BookingServiceTest).
Слайс-тесты контроллеров: тестирование HTTP-контрактов через MockMvc (TripControllerTest).
Запуск тестов:
```
mvn clean test
```
